# 无人值守长跑（overnight / 长任务）

用户说"过夜跑 / 长任务 / 我睡了 / 无人值守推进到底 / 挂机做完"时，作为 herdr 指挥官按本框架执行。适用于任何用户不在场的多任务长跑，不限于夜间。框架经真实整夜实战验证（7 任务并行、12+ PR 合入、零人工干预收口）。

用户只需提供两样：**任务清单**（原文转发给 worker，一字不改）＋**本次特有的预授权**（见下）。其余全部由本框架接管。

## 开工前（唯一一次与用户交互）

把任务分解、worker 分配、合并顺序、裁决判据表发给用户确认。确认后进入无人值守，全程不再问用户任何问题。

## 执行框架

**两阶段**：每任务先分析后实现。分析写入各自 worktree 的 `ANALYSIS.md`；指挥官读后按授权直接裁决推进，不等用户。

**决策授权**：无人值守期间指挥官全权拍板，判据：符合项目 docs 设计原则、极简无冗余、可逆优先；拿不准选改动面小的方案并记录备选。以下三类默认只做到设计文档为止、留用户回来拍板（用户预授权过的除外）：
1. 计费/价格/资金规则
2. 对外部平台的承诺性接口契约（对外文档一律标 Draft，不做发布动作）
3. 生产环境、密钥、外部服务注册（一律本地占位配置跑通，需注册的列清单）

**重叠调度**：多个任务碰同一片代码时，分析可并行，实现由指挥官排串行合并顺序，后合并者 rebase 前者；禁止两个 worker 同时改同一目录。

**质量门**：每个实现必须走完 worker 本地验证（裸退出码）→ 送审 → `/review` 对抗审查 → 发现清零 → 合并。UI 改动用 ui-craft / impeccable 规范并附截图取证。

**落盘**：每任务的分析、裁决及理由、review 结论写进该 worktree 的 `REPORT.md`；指挥官维护 `OVERNIGHT.md` 总账作追溯黑匣子（不要求用户读）。

**异常**：worker 卡住指挥官来解（supervisor 会推送 blocked 与疑似卡死通知）；配额耗尽或同一错误两次修不动 → 该任务标 BLOCKED 写明完整现场，转推其他任务；禁止空转等待，禁止打扰用户。

**收口**：全部合并后开收口 worker 做跨任务一致性检查、死代码清理、文档同步；按验收纪律的异步验证层判据清理全部 worker tab 与 worktree。

**交付形态**：终态 = 全部合并 + 清场完毕。给用户发一条总汇报：每任务一行（做了什么 / 合并状态 / 需要知道的一件事），BLOCKED 项单独列出。用户只读这条消息。
