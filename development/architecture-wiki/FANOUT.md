# Fan-out 并行产页

首次建立的模块页用 orchestrator-worker 单波并行：你是编排者，每个模块页派一个工人，verify 对账。工人彼此不可见，跨模块论断由你收口。

## 派工

按 code-map 输出切分模块后，给每个工人一张任务卡，四要素齐全：

- 目标：产出一页完整的 `docs/architecture/wiki/modules/<name>.md`，含 sources frontmatter 与 SKILL.md 规定的固定四节（职责、对外接口、数据怎么流、改动指南），直接写入该文件。
- 预置事实：该模块的文件清单及每个文件的 imports/exports/loc 摘要，从 code-map 输出切片粘入任务卡；工人从这里出发读码，不从零探索。
- 边界：读码限于分配文件及其一跳 import；只写自己那一页，页面文件互不重叠。
- 输出契约：正文每条论断指回具体文件；点名的每个 symbol 已确认存在于所引文件；每条 sources 行的哈希来自 `git hash-object` 实际运行结果。

任务卡不提渲染、lint 等后续步骤。所有工人同一波发出，任务之间无依赖，工人模型取编排者同级或低一档。

## 收口

工人全部返回后由你完成：

1. 对账：逐页核对——页面声称的依赖与导出和 code-map 图上的边一致、每条论断指回具体文件、深度撑得起模块职责一节。任何一项不过的页派新工人重写，任务卡附上原任务卡、原页面和具体差错。
2. 亲自写 index.md、system.md、data-flow.md——跨模块论断需要全局视野，不派工；对账时已通读模块页，直接下笔。
3. 回到 SKILL.md 步骤 3 运行 verify。报错页同样派新工人重写，返工永远是新工人，完成的工人收不到后续消息。
4. verify 通过即收口完成，继续 SKILL.md 步骤 4。
