# Prototype（一次性原型）

原型是**写完就扔、用来回答一个问题的代码**。问题决定形状；空对空讨论超过两轮就该停下来跑一个原型，让事实说话。

## 选分支

- **"这个逻辑/状态模型对吗？"** → [LOGIC.md](LOGIC.md)：搭一个小终端交互程序，把状态机推过纸上想不清的用例
- **"这个东西该长什么样？"** → [UI.md](UI.md)：在一个路由上生成几个结构迥异的变体，URL 参数切换，底部浮条翻页挑选

两个分支产物完全不同，选错整个原型就白做。真拿不准且用户不在场：后端模块 → 逻辑分支；页面/组件 → UI 分支，并在原型顶部注明假设。

## 两个分支共同的规则

1. **生来就是扔的，且明确标记**。放在它服务的模块/页面附近（上下文明显），命名让人一眼看出是原型不是生产代码。UI 原型路由遵循项目现有路由约定，不发明新顶层结构
2. **一条命令能跑**。挂到项目现有任务运行器（package.json scripts / justfile / Makefile），用户不需要记路径
3. **默认不持久化**。状态放内存。持久化是原型要*检验*的对象，不是它的依赖；问题确实涉及数据库时用明确标记 "PROTOTYPE — 可删" 的临时库/文件
4. **跳过打磨**。不写测试、不做超出"能跑"的错误处理、不抽象。快就是目的
5. **暴露状态**。逻辑分支每次操作后打印完整状态；UI 分支每次切换变体即时可见
6. **答案落袋后删除**。验证过的决定并回正式代码，并入 commit 的 message 里记一行"原型验证了什么问题、结论是什么"；原型文件直接删除，不留分支不留残留——结论已经活在正式代码里，原型尸体是负债
