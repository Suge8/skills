# Better Test（让测试更好）

使命一句话：**测试链越完善，flow 的机器验收覆盖面越大，假完成越少**。与其收工时人肉取证（治标），不如把验证能力沉淀进链（治本）。本 skill 管链的一生：建、养、还债。说法纪律（报告二选一、禁"应该可以了"）在系统规范，不在这里。

## 职责一 · 建链（项目首次接触时体检）

达标四问（全 yes 才达标）：

1. agent 能独立运行，不需要人肉点击？
2. 无头或隔离运行，不抢用户的鼠标/键盘/视口？
3. 结果确定，能重复跑出同样结论？
4. 能断言具体行为（DOM/响应体/日志内容），而不是"没崩就算过"？

对照 [references/toolchains.md](./references/toolchains.md) 判断本项目该用什么链。不达标：报告差距和工作量 → 用户一句话批准 → 施工。**建链最小形状**：一个能跑的 harness + 当前最需要的一条用例，套件靠职责二复利攒出，不一次建大教堂。建链本身要验证信号真实：跑一个已知会过的用例 + 一个已知会挂的用例。

与 project-setup 的分工：setup 体检发现缺链（只报告），本 skill 施工。

**选型纪律**：toolchains.md 是速查表不是永恒真理——建链前花一次搜索核实它仍是当前官方/社区主流推荐（context7/exa），发现更优方案先更新速查表再施工。禁止凭训练记忆选型。

## 职责二 · 养链（每次改动收工时的一个问题）

> **这个改动的行为，链上有覆盖吗？**

- 有 → 跑它，绿了就是证据，收工
- 没有且可覆盖 → 就势补一条用例再收工：bug 修复必沉淀回归用例（diagnose Phase 5 的产物直接入链）；新行为补对应断言
- 没有且链够不着（动效手感、真机交互、视觉美感）→ 转职责三取证，并记一笔债

## 职责三 · 取证兜底与还债

链够不着的行为，按优先级临时取证：

1. **browser-dev**：真实打开页面，截图 + console + network
2. curl / CLI 直接打接口，断言响应内容
3. 带断言的日志——grep 到预期日志行才算，不是"进程没退出"
4. **computer-use**（桌面 app 兜底）：读控件/截图取证；它操作真实桌面，只作兜底不算链，需用户不在操作电脑时进行
5. 都不行 → 给用户最短验证清单：打开哪 → 点哪 → 预期看到什么，明说"未验证，需要你验证"

**取证纪律**：本条回复里跑出来的才算证据（上一轮的结果不算）；读完整输出，截图要真的看图；走和用户相同的操作路径。

**还债规则**：同一条路径第二次人肉取证 = 该转成链上用例的信号。临时取证是债，债堆多了就是职责一的建链需求。

## 链的质量红线（测试代码也是代码，同受工程约束）

- **快**：单测毫秒级、整链分钟内——链要快到 agent 愿意频繁跑；慢链没人跑，等于没链
- **确定**：固定 seed/时钟/网络，禁止 sleep 等就绪（用条件等待）；flaky 零容忍——flaky 测试比没测试更毒，它教会所有人忽略红色
- **锦利**：一条用例验一个行为，断言具体结果不断言实现细节（系统规范的测试反作弊条适用）
- **干净**：无僵尸 skip、无死用例、重复 setup 提 fixture；链本身定期接受 optimize 减法审计

## 说法示例（格式的事实源在系统规范）

> ✅ 已修复 —— 证据：`bun test pairing` 12/12 绿（含本次新增的 relay 回收回归用例）。
>
> ⚠️ 改动已做，未验证 —— 原因：P2P 打洞需两台真机跨网段，链够不着。请验证：手机 4G + 电脑 Wi-Fi 各开一端，扫码后看标识是否 10s 内从 relay 变 p2p。已记债：此路径待接入连接状态日志断言。

同一问题被用户第二次报"还是不行"：先承认上轮验证不充分、说明漏在哪，重新取证；禁止不检讨直接再改。
