# Handoff（会话交接）

把当前会话压缩成新 agent 能直接开工的交接包。新 agent 没有你的上下文，也没有你的错觉——交接文档最有价值的部分往往是"踩过的坑"，它防止下一个 agent 把失败路径重走一遍。

## 产出两样东西

**1. 交接文档**，写到系统临时目录（不污染仓库、不会被误提交）：

`/tmp/handoff-<项目名>-<YYYYMMDD-HHmm>.md`

结构（无内容的节直接删）：

- **目标**：这项工作最终要达成什么，一两句
- **现状**：做到哪了，哪些已验证、哪些只是改了没验证
- **关键决策与理由**：本会话拍板的技术决策，各配一句为什么——防止下一个 agent 当垃圾重构掉
- **踩过的坑**：试过但失败的路径 + 失败原因。修复循环中转交时这是最重要的一节，明确写"不要再试 X，已失败 N 次，原因是 Y"
- **未决问题**：还没拍板的事，别让下一个 agent 以为已经定了
- **下一步**：按顺序列，第一步要具体到能直接执行
- **相关文件**：涉及的文件绝对路径清单
- **建议 skills**：下一个会话该用哪些 skill（如 diagnose、flow-better-test、ship）

**2. 启动提示词**，直接打印在回复末尾的代码块里，用户原样粘贴到新会话：

```
读取 /tmp/handoff-<...>.md 交接文档。先复述你对目标和现状的理解（两三句），确认无误后用户同意再开工。
```

## 规则

- 不复制已有 artifact（plan、spec、commit、diff、ADR）的内容——写路径引用
- 脱敏：API key、密码、token 一律不进文档
- 用户传了参数：把参数当作下一个会话的焦点，文档围绕它裁剪，无关内容砍掉
- 文档长度以"新 agent 五分钟读完能开工"为准；超了说明压缩不够，不是信息太多
