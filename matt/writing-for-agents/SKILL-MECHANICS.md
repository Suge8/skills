# Skill 机制（Pi）

[`writing-for-agents`](SKILL.md) 的 skill 专属分支：当文档是一个 skill 时，哪些内容会变化——frontmatter、调用方式选择和路由 skill。除此之外，关于如何编写它的一切都在 `SKILL.md` 的通用参考中。

## 调用方式

有两种选择，取舍的是两种负载：

- **模型调用**的 skill 保留 `description`，这样 agent 可以自主触发它——其他 skill 也能找到它。你仍然可以输入它的名称：模型调用始终 _包含_ 用户调用权限；description 只会增加 agent 发现它的机会，绝不会移除人的调用权限。description 是 skill 顶层的上下文指针，被强制始终加载——用持续的上下文负载换取可发现性。内容全是参考资料的模型调用 skill 也是共享参考资料的一个归处：另一个 skill 可以调用它，因此多个 skill 需要的参考资料可以集中在一处。机制：省略 `disable-model-invocation`，并编写一个面向模型的 description，其中包含触发分支（`SKILL.md` 中关于编写指针的规则全部适用）。
- **用户调用**的 skill 设置 `disable-model-invocation: true` 后，不进入 Pi 的自动技能列表；显式命令和已知路径仍可读取，其他 skill 也可通过明确指针引用。description 面向人类写一行摘要。

需要模型自行发现时才开放模型调用；只通过手动命令或明确路径指针使用的 skill 可以保持手动。

共享参考资料按职责放置，通过明确路径引用，不因手动调用而强制迁移。

## 按调用方式拆分

调用方式是拆分依据之一（按顺序拆分见 `SKILL.md`）：当存在一个应该自行触发的独立前导词——一个你确实会在提示词中使用的触发词——或其他 skill 需要从自动列表发现它时，就拆出一个模型调用的 skill。新 skill 的 description 会带来上下文负载，因此这种独立触达必须值得付出代价。

## 路由 skill

当用户调用的 skill 多到你记不住时，可以用**路由 skill**消除这份累积的认知负载：由一个用户调用的 skill 列出其他 skill 以及何时触达每一个，让人只需记住一个 skill，而不是许多个。路由可以提供明确的读取路径，但读取不等于获得执行授权。
